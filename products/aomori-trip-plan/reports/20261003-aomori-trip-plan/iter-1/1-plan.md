## 8. 作成エージェントへの指示

- 文体はです・ます調、箇条書きは体言止め可。表記(全角/半角、数字は半角、「約3時間」「〜」の書き方)をデッキ内で統一する。
- ブリーフの要望「説明されすぎない雰囲気」をスライドのトーンにも反映する。1枚の文字は少なく、余白を残す(V-5)。由来や歴史の解説を長く書かない。形容詞を重ねた宣伝調(「絶景」「必見」など)を避ける。
- 本文スライドが 12 枚あるため、3章の5セクションを `# セクション名` の扉ブロックで作る。タイトルの直後の最初のブロックを扉にし、扉ブロックには見出し以外を書かない。
- 外部データを使うスライド(#2〜#10)には、末尾に出典を1行で書く。形式は「出典: [資料名](URL)(2026年10月取得)」。リンク文言は資料名にし、「こちら」などにしない。#10 は複数の出典を1行にまとめてよい(既出のため「出典: 各スライドに記載」としてもよい)。
- 数値は4章の表の値だけを使う。運賃・料金・車の所要時間・店の営業時間は書かない。
- 位置や色だけで参照しない(「右の図」「青い線」などは不可。「ルート図」「新幹線の区間」と書く)。
- #10 の表は Markdown の表記法で見出し行を付ける(日付 / 朝 / 昼 / 夜・宿)。各セルは短い語句にする。例: 1日目 10/31(土): 東京→八戸(新幹線)/ 種差海岸を歩く / 八戸の横丁・八戸泊。2日目 11/1(日): 館鼻岸壁朝市 / 新青森から車で弘前のりんご畑 / 青荷温泉泊(道の駅虹の湖から送迎)。3日目 11/2(月): 黒石・こみせ通り / つゆやきそば / 新青森→東京(新幹線)。
- #12 は箇条書き・図を使わず、候補日と短い誘いの言葉だけにする。
- 図は 5章の仕様どおり `images/route-overview.svg` の1点だけ。それ以外の画像は作らない(写真の代用イラストも作らない)。
- 新規デッキのため、既存画像の削除は不要。`npm run build -- aomori-trip-plan`、`npm run check -- aomori-trip-plan`、`npm run pdf -- aomori-trip-plan` で、目次(セクション名5項目)を含めはみ出しがないことを確認する。
