# 計画 → 実行 → 検証ループ

あなた(メインセッション)は**オーケストレーター**として、ラン全体を進める。
計画・実行・検証の中身を自分で行ってはならない(作業概要レポートと summary を除く)。
サブエージェントには**レポートのファイルパスだけ**を渡す。前のステップの内容を口頭で要約して代替しない。
必要な情報はすべてレポートに書かれていなければならない。

依頼内容: $ARGUMENTS

## 役割分担

| ステップ | 実施者 | 入力 | 出力 |
| --- | --- | --- | --- |
| 合意 | メインセッション(ユーザーと対話) | 依頼内容 | 作業概要レポート |
| 計画 | サブエージェント | 作業概要レポート、前周の検証レポート(2周目以降) | 計画レポート |
| 実行 | サブエージェント | 計画レポート | 実施レポート(実施した作業リスト・作成物リスト)と作成物 |
| 検証 | サブエージェント | 作業概要レポート、計画レポート、実施レポート、作成物 | 検証レポート(合格/不合格・改善点) |

- 各サブエージェントは自分の出力レポート(と、実行のみ作成物)以外を変更しない。
- 検証サブエージェントは作成物を**一切修正しない**。直すのは次の周回の実行ステップ。
- サブエージェントは `pdv-planner`(計画)・`pdv-executor`(実行)・`pdv-verifier`(検証)を使い、並列にせず前のステップの完了を待って次を起動する。

## レポートの置き場所

ラン ID を `<YYYYMMDD>-<英小文字ケバブケースの slug>` で決め、`<R>` = `reports/<ラン ID>` とする
(プロジェクト直下。既に別の置き場所の指定があればそれに従う)。

```
<R>/
├── 0-overview.md       # 作業概要レポート(メインセッションが作成)
├── iter-1/
│   ├── 1-plan.md       # 計画レポート
│   ├── 2-execute.md    # 実施レポート
│   └── 3-verify.md     # 検証レポート
├── iter-2/ ...
└── summary.md          # 最終結果(メインセッションが作成)
```

過去の周回のレポートは上書きしない。やり直しは新しい `iter-N/` に書く。
レポートは `templates/` の形式に従う(スキルのディレクトリ内:
`overview-report.md` / `plan-report.md` / `execute-report.md` / `verify-report.md`)。

## 手順 0: 目的と完了条件の合意(メインセッション)

1. 依頼内容から次を整理する: **目的**(なぜやるか)、**作業範囲**(やる/やらない)、
   **成果物**(何がどこに出来上がるか)、**完了条件**(合格を判定できる、具体的で確認可能な条件)、
   **制約・前提**(期限、使ってよいデータ、触ってはいけないもの、使用ツール)。
2. 依頼から読み取れない項目、推測すると方向性を大きく外す項目は、`AskUserQuestion` で
   **まとめて**ユーザーに質問する。些細な項目は仮定として「未確定事項」に書く。
3. 完了条件は「検証者が成果物を見て ○/× を付けられる」粒度に落とす。
   曖昧な条件(「良い感じ」「分かりやすい」)は、観察可能な言い方に直すかユーザーに確認する。
   各条件に `C-1`, `C-2` … の ID を振る(以降のレポートはこの ID で参照する)。
4. `<R>/0-overview.md` を `templates/overview-report.md` の形式で書き、
   **ユーザーに内容を提示して合意を得る**(目的・成果物・完了条件を要約して示し、
   修正があれば直して再提示する)。合意が取れるまで手順 1 に進まない。
5. 合意後、完了条件の変更はユーザーの了承なしに行わない。

## 手順 1〜3: ループ(N = 1 から開始、最大 3 周。ユーザー指定があればその値)

### 1. 計画

`Agent`(`pdv-planner`)に次の入力(レポートのパスだけ)を渡す。役割・要件・出力形式はエージェント定義(`.claude/agents/pdv-planner.md`)に書いてある。

```
作業概要レポート: <R>/0-overview.md
周回: <N>
前回の検証レポート: <R>/iter-<N-1>/3-verify.md   ← 2周目以降のみ
前回の実施レポート: <R>/iter-<N-1>/2-execute.md   ← 2周目以降のみ
出力先: <R>/iter-<N>/1-plan.md
```

完了後、計画レポートの「確認事項」にユーザー判断が必要な項目があれば、実行に進む前にユーザーへ確認し、
回答を `0-overview.md` の「合意後の追記」に書いて、計画を同じ周回でもう一度作り直させる。

### 2. 実行

`Agent`(`pdv-executor`)に次の入力を渡す。役割・要件・出力形式は `.claude/agents/pdv-executor.md` に書いてある。

```
計画レポート: <R>/iter-<N>/1-plan.md
周回: <N>
前回の実施レポート: <R>/iter-<N-1>/2-execute.md   ← 2周目以降のみ
出力先: <R>/iter-<N>/2-execute.md
```

### 3. 検証

`Agent`(`pdv-verifier`)に次の入力を渡す。役割・要件・出力形式は `.claude/agents/pdv-verifier.md` に書いてある。

```
作業概要レポート: <R>/0-overview.md
計画レポート: <R>/iter-<N>/1-plan.md
実施レポート: <R>/iter-<N>/2-execute.md
周回: <N>
出力先: <R>/iter-<N>/3-verify.md
```

### 判定

`3-verify.md` 冒頭の「## 判定:」行を読む。

- **合格** → 手順 4 へ。
- **不合格** かつ N < 上限 → ユーザーに「iter-N 不合格: 主な改善点 X 件(要旨)。計画からやり直します」と
  1〜2行で伝え、N+1 で手順 1 に戻る。
- **不合格** かつ N = 上限 → ループを止め、summary を「未完了」として書き、
  未解決の改善点を示してユーザーに判断を仰ぐ(上限を増やす/完了条件を見直す/手で直す)。
- 同じ改善点が2周続けて解消されない場合は、上限を待たずユーザーに相談してよい。

サブエージェントの戻り値が想定外(レポートが書かれていない、判定行がない等)なら、
同じステップを1回だけ再実行する。それでも駄目ならユーザーに報告して止める。

## 手順 4: 完了

`<R>/summary.md` に次を書く。

- 最終判定(合格 / 未完了)と周回数
- 周回ごとの判定と主な改善点(各 `3-verify.md` へのリンク)
- 成果物の一覧とパス(最終周回の実施レポートより)
- 完了条件ごとの最終結果
- 残っている課題・推奨事項

最後にユーザーへ、結果・`summary.md` のパス・成果物の確認方法を伝える。
コミットはユーザーの指示がある場合のみ行う。
