# スライドの記述ルール

`products/<name>/content/slides.md` と `products/<name>/content/images/` を作成・編集するときのルール。
記法の詳細は README の「コンテンツの追加・編集」を参照。

## 構成

- 先頭はフロントマター(`author`, `date`)→ `# タイトル` → サブタイトル → `---`。
- 本文スライドは `---` で区切り、必ず `## 見出し` で始める。見出しは目次スライドに
  自動で並ぶため、**見出しだけを順に読んでストーリーが分かる**ように書く
  (「概要」「その他」のような中身のない見出しは避け、主張を短く書く)。
- 見出しの長さ: 1280×720 では、`##` 見出しは全角 20 字程度(半角英数字は 0.5 字で数える)を
  超えると2行になる。図のあるスライドは、見出しが2行になると本文が 720px からはみ出す
  (`npm run pdf` の「はみ出している」警告)ため、`##` 見出しを1行に収める。
  タイトル(`#`)・セクション名が2行になる場合は、語の途中で切れないよう、句の切れ目が
  1行目の末尾に来る長さにする。箇条書きの1項目も、1行に収まらない場合は語の途中で
  折り返さないよう短く書く。
- 目次スライドは自動生成されるので、手で書かない。
- 目次の項目は **6 項目以内** にする。1280×720 で1行の見出しは 7 項目まで収まり、
  8 項目以上(見出しが折り返す場合はそれ未満)で目次がスライド外にはみ出す。
  本文スライドが 7 枚以上になる場合は、話のまとまりごとに複数スライドを
  **セクション** にまとめ、目次にはスライドの見出しではなくセクション名を載せる。
  6 枚以内ならセクションも扉スライドも作らない。
  - セクションは `---` で区切ったブロックに `# セクション名`(h1)だけを書いて作る。
    そのブロックがセクションの扉スライドになり、次の扉までの `##` スライドがそのセクションに属する。
    セクションが1つでもあると、目次にはセクション名だけが自動で並ぶ。
  - スライドタイトルはセクションを使う場合も `##` で書く。
  - セクションを使う場合は、タイトルの直後(最初の本文ブロック)を扉にする。
    扉ブロックに見出し以外を書くと、ビルドがエラーになる。
  - セクション数は 6 以内、1セクションは 2 枚以上のスライドで構成する。
  - セクション名は、そのセクションのスライドに共通する主張を短く書く
    (「概要」「その他」は不可)。セクション名だけを順に読んでストーリーが分かること。
  - 計画レポートのスライド構成表に、各スライドが属するセクションを明記する。
  - `npm run pdf -- <name>` で目次スライドに「はみ出している」警告が出ないことを確認する(F-DENSITY)。
- スライド内の小見出しは `###` 以下を使う(`#` / `##` はスライドの区切りとして解釈される)。

## 1スライド1メッセージ

固定の合格基準 F-ONEMSG に対応する作成方針。

- 1枚のスライドで伝える主張は1つに絞る。主張は「〇〇は△△だ」の形で1文に書ける
  ものにする(書けなければ主張が定まっていないか、2つ以上混ざっている)。
- `##` 見出しにはその主張を書く。トピック名ではなく結論を書く
  (例: 「売上推移」ではなく「売上は3年で2倍に伸びた」)。
- 本文・表・図は見出しの主張を支える根拠や具体例だけにする。主張と関係しない情報や
  別の主張は、削るか別のスライドに分ける。
- 2つ目の主張が出てきたら、「〜と〜」で見出しをつなげず、スライドを分ける。
  比較(A と B の違い)は「違い」自体を1つの主張として書けるなら1枚でよい。
- 図・グラフも、そのスライドの主張を示すものを1つ選ぶ。同じ主張を補強する場合を除き、
  1枚に複数の図を並べない。

## 視覚化

固定の合格基準 F-VISUAL に対応する作成方針。文字だけのスライドを続けず、
主張を図で一目で分かるようにする。

- 本文スライドごとに「この主張は図にできるか」を検討する。下の表の内容を含むスライドは、
  原則として図(SVG)で示し、文章は図の補足にとどめる。

  | スライドの内容 | 図の型 |
  | --- | --- |
  | 数量の比較・内訳 | 棒グラフ、横棒グラフ、積み上げ棒 |
  | 数量の推移 | 折れ線グラフ、棒グラフ |
  | 手順・流れ・因果 | フロー図(矢印でつないだボックス) |
  | 日程・時系列 | タイムライン |
  | 場所・移動 | 簡略化した地図・ルート図 |
  | 構成・関係・分類 | 構造図、ツリー、ベン図、2×2 のマトリクス |
  | 比較(A と B、ビフォー・アフター) | 左右に並べた対比図 |
  | 1つの重要な数値 | 数値を大きく示した図(数値と単位・比較対象を併記) |

- 図にしたスライドの割合は、本文スライド(セクションの扉・参考文献スライドを除く)の
  **半数以上**を目安にする。図のないスライドは、計画レポートの 3章に理由を書く
  (例: 「結論と依頼事項を言葉で示すため」)。表は図の代わりにしない
  (表は正確な値の一覧で、傾向や関係は図のほうが伝わる)。
- 図は主張を示すものにする。主張と関係しない飾りのイラスト・アイコンだけの画像・
  ストック写真は数に入れず、置かない(F-1.4.5 / F-ONEMSG)。
- 図のあるスライドの文章は、箇条書き 3 項目以内、本文 120 字程度までにする
  (図は最大 252px の高さで表示されるため、文章が多いと 720px に収まらない)。
  文章で言い直すのではなく、図から読み取ってほしい点だけを書く。
- 図の中の文章は、ラベル・数値・短い語句(1要素 15 字程度まで)にする(F-1.4.5)。
- 分岐のあるフロー図(選び方・判断の手順)は、各問いの答えを漏れなく用意する
  (「はい/いいえ」「〜以上/〜未満」のように、答えの範囲が重ならず、すべての場合を含む)。
  答えの組み合わせのどれにも行き先を置き、合う選択肢がない組み合わせは、図か本文で
  「該当なし(理由)」と示す。計画レポートの「図の中の要素」には、すべての答えの組み合わせと
  行き先を書く。
- 写真・地図画像などのラスター画像は、ブリーフでユーザーが提供したもの、
  または利用条件(ライセンス・クレジット表記)を計画レポートに記載したものだけを使う。
  Web 上の画像を無断で使わない。地図は SVG で簡略化して描くのを基本にする。

### 固有名詞の画像

商品・場所・人物など固有名詞を説明するスライド(その固有名詞が主張の主題であるスライド)には、
その画像(製品写真・施設の写真など)を1枚載せる。固有名詞が比較グラフのラベルとして
出るだけのスライドには載せなくてよい。載せないスライドは、計画レポートの 3章に理由を書く。

- 画像の出典と利用条件は、上の写真の規定に従う(ユーザー提供、または利用条件を計画に記載したもの)。
- 固有名詞の画像は F-VISUAL の「図」に数えない。主張を示す図は別に用意する。
- 画像のあるスライドの文章は、箇条書き 6 項目以内にする。「3 項目以内・120 字程度」は
  SVG の図があるスライドに適用する。
- 配置は箇条書きの右側への横並びにする(縦に積むと 720px に収まらない)。
  テンプレートは画像を縦に積むので、生の HTML の `div` で並べ、箇条書きは Markdown のまま空行で挟む。

  ```html
  <div style="display: flex; align-items: center; justify-content: space-between; gap: 32px;">

  - 箇条書き

  <img src="images/xxx.png" alt="..." style="height: 200px; width: auto; flex-shrink: 0; margin: 0;">
  </div>
  ```

- 表示の高さは 200px を既定とし、最大 252px にする。同じ型のスライドでは高さをそろえ、
  200px 未満にしない。252px で本文が 720px に収まらないときは 200px に下げる。
- 画像の横は文章の幅が狭まる。箇条書きが語の途中で折り返さないかを確かめ、折り返す場合は文言を短くする。
- キャプションは付けず、出典は注記に「出典・写真: 資料名[[n]](#ref-n)」の形で書く
  (引用番号リンクの形式は「出典と参考文献」に従う)。
- alt には、製品名と、見えるもの(色・形・素材・特徴)を具体的に書く。

## 表

- 表の高さは、見出し行(th)を含む行数 × 約57px(セルが1行に収まる場合。折り返すと行が増える)で見積もる。1280×720 の本文領域は約416px。
- `###` 小見出し・注記・写真(高さ200px)と同じスライドに置く表は、見出し行を含めて **4 行(約228px)まで**にする。5 行以上は約285px + 表以外の約133px で本文領域を超える。
- 行を削れない場合は、スライドを分ける。分けるときは、各スライドの見出しが1つの主張になるようにする。
- 上の数値は `src/style.css` のセル余白・文字サイズに依存する。テンプレートを変えたときは、実測して更新する。

## 文章

- 箇条書きは 6 項目以内、本文は 250 文字以内を目安にする。
  収まらなければスライドを分ける(1スライド1メッセージを守った結果、収まるのが普通)。
- 文体はデッキ内で統一する。見出し・本文の文は「です・ます」調で書く。箇条書きは常体
  (体言止め、または「〜する」「〜だ」)にそろえ、敬体と混ぜない(提案・呼びかけも
  「〜を比べる」のように常体で書く)。
- 表記の既定: 和文と英数字の間、数字と単位の間に半角スペースを入れない(製品名・型番などの
  固有名の固定形の内部は除く)。複数の出典で同じ語の表記が違う場合(ダイヤル/ダイアルなど)は、
  デッキ内で1つにそろえる。
- 「右の図」「赤い部分」のように位置や色だけで参照しない。
- リンクは行き先が分かる文言にする(`[2025年度 決算資料](https://...)`)。

## 出典と参考文献

固定の合格基準 F-SOURCE に対応する書き方。外部の資料を使うデッキは、各スライドには
出典を簡潔に書き、URL などの詳細はデッキ末尾の参考文献スライドにまとめる。

- 各スライドの出典: 本文末尾の注記に、短い資料名と**引用番号リンク**だけを書く。
  URL・取得日はここに書かない。

  ```markdown
  <small>出典: 旅行読売「種差海岸」[[1]](#ref-1)、新幹線ガイド「はやぶさ」[[2]](#ref-2)</small>
  ```

  - 本文末尾の `<small>` だけの段落は、ビルド時に注記(`<footer class="notes">`)として
    本文から切り出され、スライドの下端にそろえて表示される。注記は本文の最後に書く。
  - 資料名は発行元とページ名が分かる程度に短くする(1件 20 字程度まで)。
  - 引用番号リンクは、資料名の直後に同じ注記の中で置く(リンク文言 `[1]` の目的を
    直前の資料名で示すため。F-2.4.4)。
  - 想定・仮定の注記(「レンタカー利用は想定」など)は、従来どおり同じ注記に書いてよい。
- 番号: デッキ内で最初に引用した順に 1 から振る。同じ資料を再び引用するときは同じ番号を使う。
  id は `ref-<番号>` とする。
- 参考文献スライド: 本文の最後のスライドを `## 参考文献` にし、引用番号の順に
  Markdown の番号付きリストで書く。各項目の先頭に `<span id="ref-<番号>"></span>` を置き、
  リストの番号と id の番号を一致させる。

  ```markdown
  ## 参考文献

  1. <span id="ref-1"></span>[旅行読売 種差海岸(tabi-mag)](https://tabi-mag.jp/ao0088/)(2026年10月取得)
  2. <span id="ref-2"></span>[新幹線ガイド はやぶさ](https://shinkansen.tabiris.com/train07.html)(2026年10月取得)
  ```

  - 各項目には資料名(リンク文言)・URL・取得年月(公開年が分かる資料は公開年も)を書く。
  - 1枚 6 項目まで(F-DENSITY)。超える場合は `## 参考文献(1/2)`・`## 参考文献(2/2)` に
    分け、2枚目のリストは続きの番号(例: `7.`)から始める。
  - 見出しは主張ではなく「参考文献」でよい(F-ONEMSG・F-2.4.6 の例外)。
  - 参考文献スライドも目次に並ぶ。セクションを使うデッキでは最後のセクションに含め、
    参考文献だけのセクションは作らない。セクションを使わないデッキでは、
    参考文献スライドも目次の 6 項目に数える。
  - 外部の資料を1つも使わないデッキでは作らない。
- 出典は日本語のページを優先する。日本語以外のページしかない場合は、参考文献リストの
  リンク文言に言語を書き添える(例: `[資料名(英語版)](URL)`)。計画レポートの出典欄にも、
  言語と日本語版の有無を書く。
- `npm run check -- <name>` は、引用番号リンクの参照先 id がない場合と、
  リストの番号と id が一致しない場合を F-SOURCE の error として報告する。

## 絵文字

固定の合格基準 F-EMOJI に対応する書き方。絵文字は、箇条書きや表で項目の種類や状態を
見分けやすくする目印としてだけ使う。使わなくてもよい(使わないデッキも合格)。

### 使ってよい絵文字

下の一覧の絵文字は、書かれた意味で使う。同じ意味には同じ絵文字を使い、
1つの絵文字に別の意味を持たせない。一覧にない絵文字も、下の「一覧にない絵文字を使う」の
手順を守れば作成中に使ってよい。

| 絵文字 | 意味 | 使用例 |
| --- | --- | --- |
| ✅ | できる・完了・合格 | `✅ 予約済み` |
| ❌ | できない・不可・不合格 | `❌ 冬季は運休` |
| ⚠️ | 注意・リスク | `⚠️ 最終バスは 17 時` |
| ❓ | 未定・要確認 | `❓ 宿泊先は未定` |
| 💡 | ヒント・提案 | `💡 平日は空いている` |
| 📌 | 要点・結論 | `📌 2日目に集中して回る` |
| 🗓️ | 日付・日程 | `🗓️ 10月12日(土)` |
| ⏱️ | 時間・所要時間 | `⏱️ 約3時間` |
| 📍 | 場所・目的地 | `📍 種差海岸` |
| 💰 | 費用・金額 | `💰 1人 約2万円` |
| 👤 | 担当者・人 | `👤 幹事: 佐藤` |
| 📊 | データ・数値 | `📊 前年比 120%` |
| 🎯 | 目的・目標 | `🎯 来期の売上 10% 増` |
| 🚃 | 交通・移動 | `🚃 新幹線で八戸へ` |
| 🍴 | 食事 | `🍴 昼は八食センター` |
| 🏨 | 宿泊 | `🏨 八戸市内に1泊` |
| ♨️ | 温泉 | `♨️ 夕方は温泉` |

- ⚠️・🗓️・⏱️・♨️ は異体字セレクタ(U+FE0F)まで含めて一覧の文字をそのまま書く。
  U+FE0F がないとモノクロの記号として表示される。

### 一覧にない絵文字を使う

一覧の意味に当てはまらない項目に目印が必要なら、作成エージェントは一覧にない絵文字を使ってよい。

- 一覧にある意味には、一覧の絵文字を使う(「日程」に 📆 を使うなど、同じ意味に別の絵文字を使わない)。
- デッキ内では1つの意味に固定し、下の「使い方」も一覧の絵文字と同じように守る。
- 1280×720 のスクリーンショットで、カラーの絵文字として表示されることと、
  字形に日付・時刻など特定の値が描かれていないこと(📅 は「7月17日」、🕒 は「3時」が描かれる)を確認する。
  モノクロになる場合は U+FE0F を付けて確かめ、それでもモノクロなら使わない(✔️ は U+FE0F を付けてもモノクロ)。
- 使った絵文字は、作成レポートの「7. 一覧にない絵文字」に意味・使ったスライド・
  一覧の絵文字では足りない理由・表示の確認結果を書く。
- `npm run check` はこの絵文字を F-EMOJI の warning として報告する。検証では合格とし、
  検証レポートの「6. 確認事項」に挙げる。振り返りレポートが「5. 新規追加すべき絵文字」に
  一覧への追加候補としてまとめる。
- 一覧と `scripts/check-slides.js` の `EMOJI` への追加は、振り返りの提案をユーザーが承認したあとに、
  ランとは別の変更として両方に行う。

### 使い方

- 絵文字だけで情報を伝えない。必ず同じ項目に意味の分かる文字を併記する
  (表のセルに ✅ だけを置かず `✅ 可` と書く)。絵文字は形と色で意味を示すため、
  単独では F-1.3.3・F-1.4.1 に反する。読み上げソフトは絵文字の名前を読むので、
  文字がないと意味が伝わらない。
- 置き場所は箇条書きの項目・表のセル・段落の先頭。1項目に1つまでにする。
- 見出し(`#` / `##` / `###`)とタイトル・サブタイトルには使わない
  (目次と読み上げに絵文字の名前が混ざり、見出しの主張が読み取りにくくなる)。
- 装飾のために並べたり、文末に感情表現として付けたりしない。
- SVG の図の中には使わない(表示がフォントに依存し、コントラストも検査できない)。
  図では文字のラベルを使う。

## 画像

- 同じデッキの `products/<name>/content/images/` に置き、`images/ファイル名` で参照する
  (他のデッキの画像は参照できない。必要ならコピーする)。
- グラフ・図は SVG で作る。`viewBox` を指定し、全面の背景 `<rect>` を
  `width` = viewBox の幅で置く(`npm run check` が背景色として扱う)。
- 画像はテンプレートで縮小表示される: 本文中の `<img>` は `max-width: 100%`
  (1280×720 で本文幅 約1100px)、`max-height: 35cqh`(1280×720 で 252px)に収まるよう
  縮小される(`src/style.css` の `.slide--content .body img`)。
  表示倍率 = min(1, 1100 ÷ viewBox の幅, 252 ÷ viewBox の高さ)。
  テンプレートの表示上限を変えた場合は、この数値も更新する。
- SVG 内の文字は、**実効サイズ(font-size × 表示倍率)で 16px 以上**にする。
  viewBox の高さが 252 を超えると縮小されるので、図は横長(例: 高さ 252 前後)で設計し、
  要素を減らして文字を大きくする。
- SVG 内の文字色は `fill` 属性で直接指定する。
  背景とのコントラスト比 4.5:1 以上(実効サイズ 24px 以上は 3:1 以上)。
- 色だけで系列を区別しない。直接ラベルや凡例のテキストを併記する。
- 図形・線は隣接色とのコントラスト比 3:1 以上。
- SVG に `<script>` やアニメーションを入れない。
- `alt` には画像が伝える内容(グラフなら結論と主要な値)を書く。
- SVG のルート要素には `role="img"` を付け、alt と同じ趣旨の `<title>` を最初の子要素として入れる
  (SVG を単体で開いたときにも内容が伝わるようにする)。
- 配色は `src/style.css` のカラーパレット(モノトーン + ティール)に合わせる。
  アクセントは面がティール、文字が青で、ほかはグレーを使う。
  - 面: `--accent`(#00b5c8)。背景とのコントラスト比が 2.28:1 で、F-1.4.11(3:1)を満たさない。
    意味を持つ線・図形・棒には、太さに関係なくティールを単独で使わない。使う場合は
    `--ink`(#222222)の縁取りを付ける(縁取りと背景が 3:1 以上になればよい)か、
    隣接する要素との境界を 3:1 以上の色で描く。文字には使わない
  - 文字・細線のアクセント: `--accent-strong`(#3335e3、青)。背景 6.98:1。ティール(#00b5c8)の上では 3.06:1 のため、ティールの面に青い文字を載せない
  - 文字: `--ink`(#222222)、`--ink-soft`(#5c5c5c)/ 背景: `--paper`(#f5f5f5)、`--surface`(#ebebeb)
  - 系列が2つ以上あるグラフは、ティールとグレーの濃淡に加えて直接ラベルや線種で区別する
  コントラスト比は `node scripts/check-slides.js contrast <前景> <背景>` で確認できる。
- ファイル名はラン内で意味が分かる英小文字のケバブケース(`sales-trend-2025.svg`)。
