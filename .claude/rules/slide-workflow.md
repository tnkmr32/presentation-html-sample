# スライド作成ワークフロー

スライドの新規作成・作り直しは、必ず `/create-slides` スキルで
**計画 → 作成 → 検証** のループとして実施する。メインセッションが直接
`content/slides.md` を書き換えてスライドを作ってはならない(誤字修正など、
ユーザーが明示的に指示した小さな手直しは除く)。

## 役割分担

| ステップ | 実施者 | 入力 | 出力 |
| --- | --- | --- | --- |
| 計画 | `slide-planner` サブエージェント | ブリーフ、前回の検証レポート(2周目以降) | 計画レポート |
| 作成 | `slide-creator` サブエージェント | 計画レポート | `content/slides.md`、`content/images/*`、作成レポート |
| 検証 | `slide-verifier` サブエージェント | ブリーフ、計画レポート、作成レポート、成果物 | 検証レポート(合格/不合格) |

- メインセッションはオーケストレーター。各ステップをサブエージェントに委譲し、
  レポートのパスを受け渡すだけで、スライドの中身を自分で書かない。
- 各サブエージェントは自分の担当範囲以外のファイルを変更しない
  (検証エージェントは成果物を一切修正しない。直すのは次の周回の作成エージェント)。

## レポートの置き場所と受け渡し

1回のスライド作成を「ラン」と呼び、ランごとにディレクトリを作る。

```
reports/<YYYYMMDD>-<slug>/
├── brief.md            # ユーザーの依頼を整理したもの(オーケストレーターが作成)
├── iter-1/
│   ├── 1-plan.md       # 計画レポート
│   ├── 2-create.md     # 作成レポート
│   └── 3-verify.md     # 検証レポート
├── iter-2/ ...
└── summary.md          # 最終結果(オーケストレーターが作成)
```

- レポートは `.claude/skills/create-slides/templates/` のテンプレートに従って書く。
- 次のステップへは**レポートのファイルパス**で引き渡す。口頭の要約で代替しない。
  次のステップが必要とする情報は、すべてレポートに書かれていなければならない。
- 過去の周回のレポートは上書きしない。やり直しは新しい `iter-N/` に書く。

## ループと終了条件

- 検証が **合格** → ラン完了。`summary.md` を書いてユーザーに報告する。
- 検証が **不合格** → 次の周回として**計画からやり直す**。計画エージェントは
  前回の検証レポートの指摘をすべて計画に反映し、どう対処したかを明記する。
- 上限は **3 周**(ユーザーが別途指定した場合はその値)。上限に達しても不合格なら
  ループを止め、未解決の指摘を添えてユーザーに判断を仰ぐ。
- 同じ指摘が2周続けて解消されない場合も、3周目を待たずにユーザーへ相談してよい。

## データの扱い

- 数値・事実・引用は、ブリーフでユーザーが提供したもの、または計画レポートに
  出典(URL・資料名)を記載したものだけを使う。**数値を創作しない。**
- 出典を確保できないデータが必要な場合、計画エージェントはそれを
  「要確認データ」としてレポートに挙げ、オーケストレーターがユーザーに確認する。
  ユーザーが仮データで良いと言った場合のみ、スライド上に「仮データ」と明示して使う。

## 合格基準

- 固定の基準: `.claude/rules/slide-acceptance-criteria.md`(毎回同じ)
- 可変の基準: 計画エージェントがランごとに計画レポートで定義する
  (目的との整合、ストーリーどおりの構成、対象者に合った表現など)
- 合格 = 固定の必須基準をすべて満たし、かつ可変の基準をすべて満たすこと。
